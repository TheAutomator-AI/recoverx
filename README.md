## 🎯 Product Thesis

RecoverX is an India-first revenue recovery agent engineered for the complex realities of Indian digital payments (UPI, RuPay, Visa/Mastercard, NetBanking, and e-Mandates).

```
Detect ➔ Diagnose ➔ Calibrate Confidence ➔ Gate Autonomy ➔ Communicate ➔ Recover ➔ Verify ➔ Follow Up ➔ Measure
```

### Core Axioms
1. **AI Reasoning $\neq$ Financial Authorization**: Diagnostic hypotheses generated by LLMs are advisory; only deterministic policy engines authorize financial actions.
2. **Confidence $\neq$ Permission**: High confidence is a prerequisite, never a bypass for financial safety invariants (cooldowns, idempotency, terminal blocks).
3. **Human Escalation is a Feature, Not a Failure State**: Safely routing ambiguous or high-value anomalies prevents catastrophic double debits and merchant chargebacks.

> *Note: This repository operates in a synthetic hackathon simulation environment. RecoverX does not move real-world financial funds.*

## 🛡️ The 12 Deterministic Policy Rules

| Rule ID | Rule Name | Description | Policy Outcome |
|---|---|---|---|
| **RULE_1** | `MAX_AUTONOMOUS_RETRIES` | Limits automated financial retries to $\le 2$ attempts | `ESCALATE` |
| **RULE_2** | `COOLDOWN_SATISFIED` | Enforces minimum cooldown ($\ge 30$ mins) between financial retries | `BLOCK` |
| **RULE_3** | `DUPLICATE_PROTECTION` | Blocks execution if an active attempt is currently in-flight | `BLOCK` |
| **RULE_4** | `TERMINAL_FAILURE_PROTECTION` | Blocks retrying expired cards / blocked accounts | `BLOCK` |
| **RULE_5** | `PREVIOUSLY_RECOVERED_PROTECTION` | Blocks attempts on payments already verified as `RECOVERED` | `BLOCK` |
| **RULE_6** | `LOW_CONFIDENCE_ESCALATION` | Escalates transactions with composite confidence $< 0.60$ | `ESCALATE` |
| **RULE_7** | `CONTRADICTORY_RECORDS_ESCALATION` | Escalates transactions with conflicting gateway/bank telemetry | `ESCALATE` |
| **RULE_8** | `HIGH_VALUE_PROTECTION` | Payments $\ge ₹50,000$ require human operator sign-off | `ESCALATE` |
| **RULE_9** | `MAX_ATTEMPT_STOPPING_RULE` | Halts recovery when total attempts exceed configured limit ($\ge 4$) | `BLOCK` |
| **RULE_10** | `IDEMPOTENCY_VERIFICATION` | Enforces deterministic SHA-256 idempotency key generation | `BLOCK` |
| **RULE_11** | `AUDIT_EVENT_REQUIREMENT` | Enforces synchronous audit event generation for all decisions | `APPROVE` |
| **RULE_12** | `COMMUNICATION_TRUTHFULNESS` | Prohibits claiming payment success before bank verification | `BLOCK` |

## 🔬 5-Factor Confidence Calibration Formula

$$\text{Composite Confidence} = (s_{\text{clarity}} \times 0.35) + (s_{\text{pattern}} \times 0.25) + (s_{\text{context}} \times 0.20) + (s_{\text{history}} \times 0.10) + (s_{\text{model}} \times 0.10)$$

* **$\ge 0.85$** $\to$ `AUTONOMOUS` Candidate (Gated by Policy Engine)
* **$0.60 - 0.849$** $\to$ `ASSISTED` (Enqueued for Human Operator Review)
* **$< 0.60$** $\to$ `ESCALATED` (Senior Operations Review)
